## 產品定位

本專案從以歌曲、歌詞與 YouTube 為核心的學習網站，轉型為「台灣人學日文的內容學習
平台」。

產品以教材內容與學習行為為核心。六大教材類型為單字、文章、對話、歌曲、文法與
測驗。歌曲仍保留，但只是教材類型之一，不再決定整個系統的資料模型與播放架構。

核心學習流程：

```text
內容學習 -> 逐句理解 -> 點擊單字或文法 -> 收藏 -> 測驗 -> 複習
```

## 問題定義

舊產品以 `Song -> Lyric -> YouTube` 為核心，造成以下限制：

- Article、Dialogue 等非歌曲教材難以自然加入。
- 教材 ID、播放狀態與 YouTube Video ID 高度耦合。
- 測驗依賴歌詞與時間軸，難以重用於一般句子。
- 全站播放器讓不需要影音的頁面也依賴 YouTube。
- 付費價值若建立在第三方影片或歌詞全文上，商業化風險較高。

## 目標使用者

- 居住於台灣或以繁體中文為主要閱讀語言。
- 日文程度涵蓋初學者至 JLPT N1。
- 希望透過真實、短篇且可理解的內容累積日文能力。
- 需要繁中翻譯、單字提示、音檔與低摩擦測驗。

### v1 交付內容

v1 要把產品從「前端寫死假資料的原型」推進到「有後端的可用產品」。

**要驗證的核心體驗：**

```text
瀏覽教材 -> 依程度篩選 -> 進入教材或展開單字
        -> 閱讀日文與繁中輔助 -> 查看重點單字／文法 -> 播放日文語音
```

**必須完成（缺一項就不算 v1）：**

- 單字、閱讀、對話三頁的資料來自 MongoDB，經 Nuxt server API 取得，不再是編譯
  進前端的 TypeScript 假資料。
- 列表的程度篩選與分頁由伺服器端完成。
- 語音可在公開環境使用，且公開使用者無法提交任意文字觸發付費合成。
- 對話的固定角色使用不同的日文人聲。
- 音檔快取（行程內記憶體即可），避免同一句重複合成。

**加分項（時間不足可延後，不影響 v1 成立）：**

- 音檔快取改為 MongoDB 持久化，重新部署後仍然命中。
- 依未配對報告補齊單字表。
- 補充教材數量。

**明確不做（延後到 v2 之後）：**

- 歌曲、文法、測驗的資料化。
- 會員登入、收藏持久化、學習紀錄、跨裝置同步。
- 管理員後台與教材編輯器。
- AI 自動發布教材。
- Cloudflare R2 與完整 Audio Asset 流程。
- 正式資料庫 migration 機制。
- 一次定稿未來六種教材的完整 schema。

實作規格見 `docs/tasks/task-011-material-api-and-seed.md`。

## 教材功能範圍

標註 `[v1]` 的是本版要交付的；其餘為長期範圍，實作時間見「版本範圍」表。

### 單字 `[v1]`

單一列表頁，不建立獨立單字詳情 route。可選擇 `N5`～`N1` 或全部程度並分頁瀏覽。

- 以 Ruby 顯示漢字讀音，可切換是否顯示假名。
- 繁體中文意思、詞性標籤；選擇全部程度時額外顯示 JLPT 程度標籤。
- 單字與例句發音。
- 在同一列表頁展開詳細內容，不另開頁面。
- 動詞標示第一類（五段）、第二類（一段）或第三類（不規則），資料保存完整常用
  活用：辭書形、ます形、ない形、て形、た形、可能形、被動形、使役形、使役被動形、
  命令形、意向形、ば條件形、たら條件形。
- UI 將活用分為基本與進階層級，避免初學者一次接收過多資訊，但不因收合而省略
  底層教材資料。
- 日文例句與繁中翻譯，例句中的目標單字以不同顏色標示。
- 單字與例句各自提供收藏按鈕；v1 只做 UI，收藏不持久化。

### 閱讀 `[v1]`

- 依 JLPT 程度篩選與分頁；文章列表與詳情。
- 整篇閱讀與單句學習兩種模式。
- Ruby、繁中翻譯、內容遮罩、播放速度與序列播放。
- 可互動的重點單字與文法註解（popover）。

### 對話 `[v1]`

固定使用 `ふふ`／`シロ`／`クロ` 三個角色，名字、頭像與 TTS 聲音由應用程式設定，
不由每份教材自行建立。

- 依 JLPT 程度篩選與分頁；對話列表、情境、角色與逐句內容。
- 閱讀模式與角色扮演練習。
- Ruby、繁中翻譯、內容遮罩、播放速度與序列播放。
- 可互動的重點單字與文法註解。
- 每個角色對應一個固定的日文 TTS voice，使對話可使用不同人聲。

v1 不支援自訂角色或每篇教材使用不同角色設定。

### 文法 `[v2]`

- 依 JLPT 程度瀏覽；繁體中文解說與日文例句。
- 播放例句音檔。
- 連結相關單字、文章或測驗。

詳細學習流程待文法頁切版時定義。v1 期間，教材內文的文法註解 `grammarPointId`
一律為 `null`，前端維持「規劃中」入口，不導向不存在的 route。

### 歌曲 `[未排程]`

歌曲保留為 `MaterialType = song`，但不再作為底層核心。

保留：Song 頁、頁內 YouTube Embed、歌詞與翻譯顯示；未來可加入歌詞單字標記、
文法標記與收藏。

移除：全站背景 YouTube 播放器、跨頁持續播放、非 Song 頁對 YouTube player state
的依賴。

原因：降低 YouTube 政策與第三方平台依賴風險；降低商業化對第三方內容的依賴；
讓其他教材能獨立運作；將付費價值建立在學習服務而非影片播放本身。

### 測驗 `[未排程]`

題型方向：聽音選擇題、閱讀選擇題、讀音選擇題、單字選擇題、句子重組。

現有 Song Quiz 只有以歌詞翻譯為核心的選擇題，且播放依賴 YouTube 時間軸，
不延續為新版測驗。正式測驗將全面重寫，音訊改為引用教材或題目的音檔資產。

正式題目來自 Question Bank，不在使用者作答時隨機產生低品質干擾項：

```text
AI 或管理者產生候選題 -> 管理者審核 -> 發布至 Question Bank -> 正式測驗使用
```

### 會員 `[v2]`

僅包含使用者登入、使用者資料識別與權限、單字收藏的資料歸屬、測驗與學習紀錄的
資料歸屬。不包含訂閱、付款或方案管理。

## 教材資料與 API 原則

- **repo 內的教材資料檔是正本，MongoDB 是可重建的副本。** 內容進 git 才有 diff、
  review 與重跑的能力；資料庫隨時可以清空重建。
  v1 的匯入只做 upsert，**不會刪除 repo 已移除但資料庫還留著的舊教材**；需要完整
  重建時先手動清空教材 collection。自動同步刪除留待之後處理。
- 已由前端畫面驗證過的 TypeScript 型別是資料契約的主要依據。
- MongoDB schema 是可演進的第一版，不視為未來所有教材的最終模型。
- 教材與內文單位沿用現有穩定字串 ID，並直接作為 MongoDB `_id`，避免兩套身分。
- API 回傳前端需要的 domain 形狀，不讓 Vue 元件依賴 MongoDB 文件細節。
- 列表 API 只回傳摘要，詳情 API 回傳完整內文與註解。
- API 必須驗證程度、分頁與 ID 等輸入，找不到教材時回傳 404。
- 不建立通用、可查任意 collection 的 API。
- AI 可協助產生候選內容，但產出必須先落成 repo 內的 TypeScript／JSON，通過型別
  與結構驗證後才匯入。不把未檢查的內容手動匯入資料庫。
- 完成條件看「涵蓋代表性資料情境」，不看筆數。

### 單字配對

教材內文的單字註解不重複保存完整單字資料，而是以自然鍵指向單字表：

```text
自然鍵 = 辭書形 dictionaryForm + 讀音 reading + 詞性 partOfSpeech
```

例如文章出現 `食べた`，註解保存的辭書形為 `食べる`，因此配對到單字表的 `食べる`
條目，而不是用表層活用形比對。

配對在**資料匯入階段**完成，不需要後台：

```text
匯入單字 -> 建立自然鍵 unique index -> 匯入閱讀／對話
        -> 以自然鍵尋找單字
        -> 命中：寫入 vocabularyItemId
        -> 未命中：保留 null 並列入未配對報告
```

未命中的註解仍可使用自己的上下文意思與備用例句正常顯示，不阻斷教材。管理者只需
查看未配對報告。未來新增後台時，再把未命中、衝突與人工修正做成管理介面。

單字身分、收藏去重與 AI 產生內容的完整模型見 `context/content-model.md`。

## 語音方向

### v1

- 語音入口只接受**內容座標**（教材類型、教材 ID、內容單位 ID），不接受任意文字。
  伺服器依座標讀取教材文字與 voice，前端無法提交任意文字或指定 voice。
- 對話依角色決定聲音，voice 名稱由伺服器端 allowlist 決定。
- 需要文字長度上限、找不到教材即 404，以及可用環境變數一鍵停用語音合成。
- 音檔快取以「文字 ＋ voice 的雜湊」為鍵，同一句只合成一次；文字修改後雜湊改變，
  自動產生新音檔，不會誤用與舊文字不一致的音檔。
- **v1 必做的是行程內記憶體快取**，這已足以滿足「同一句重複播放不重複付費」。
- 改為 **MongoDB 持久化快取**（重新部署後仍命中）是加分項，不是 v1 的成立條件。
  之所以先選 MongoDB 而非物件儲存服務：專案已有 MongoDB，v1 的資料量不足以讓
  多接一個服務產生效益。

### 之後

- Cloudflare R2 與 CDN；遷移時只有快取讀寫的實作要換。
- 教材發布時批次預先產生音檔，使用者第一次播放的即時產生只作為補救流程。
- 完整的音檔資產狀態機、版本與孤兒音檔清理。
- 跨 provider fallback。

## 非目標

- 英文學習。
- 訂閱付款。

## 產品原則

- **學習優先：** 每個功能都應服務於理解、收藏、測驗或複習。
- **內容可追溯：** 單字、註解與題目應能回到來源句子。
- **AI 可審核：** AI 只建立候選內容，不直接成為正式教材。
- **第三方可替換：** YouTube、TTS 與儲存服務不得成為 domain primary key。
- **聚焦市場：** 只正式支援 `zh-TW -> ja`。
- **資料可重建：** 內容正本在 repo，資料庫可清空重來。

## 風險與待驗證事項

| 風險 | 處理方式 |
| --- | --- |
| Schema 後續需要調整 | 匯入可重跑、資料庫可重建、API 隔離資料庫結構 |
| AI 內容格式錯誤 | 匯入前型別／結構驗證與人工抽查 |
| 單字找不到或自然鍵衝突 | 保留 null、輸出報告，不阻斷教材 |
| TTS 成本或公開濫用 | 只接受既有內容座標、voice allowlist、長度上限、可一鍵停用 |
| 教材量不足 | 優先確保代表性與完整學習流程，數量另行追蹤 |
| 閱讀與對話能否帶來回訪 | 待實際使用資料驗證 |
| 人工審核 Question Bank 的成本 | 測驗未排程，屆時重新評估 |
| 第三方內容授權 | 歌詞、翻譯、新聞等來源需另行確認 |

## 建議衡量指標

- 教材開始率與完成率。
- 翻譯顯示率與語音播放率。
- 每篇完成教材的單字收藏數。
- 收藏後七日內的複習率。
- 測驗開始率、完成率與答題正確率。
- 題目被管理者退回或修改的比例。
