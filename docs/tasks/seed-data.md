# 教材資料產生規範（給 ChatGPT）

> 這份文件貼給 ChatGPT，請它依此格式產生 Ofufu 的**閱讀（reading）／對話（conversation）**教材假資料。
> ChatGPT 不需要懂本專案，只要照本文欄位、括號記法與規則輸出即可。
> 產出後由使用者貼進 `app/data/materials/reading.ts`、`conversation.ts`。

---

## 0. 你的角色與任務

你要產生「**日本母語人士在真實情境下自然會說**」的閱讀短文或情境對話教材（給繁體中文使用者學習），並替內文的**漢字標讀音**、標出**符合該程度的重點單字**與**符合該程度的文法**。輸出**TypeScript 物件**，直接可貼進資料陣列。所有翻譯與說明用**繁體中文**（教材內的日文保留原文）。

所有內文與對話都應**符合角色身份、場合與禮貌程度，不得只追求文法正確**。若自然表達與 JLPT 範例句衝突，**優先採用自然表達**，再從其中挑選適合該等級的重點單字與文法。

請把自己當成**日本劇本編輯**，而不是 JLPT 出題者：你的目標是「日本人真的會這樣說」，而不是「每一句都像教科書例句」。

### 教材品質優先順序（最重要；規則衝突時照此排序）

1. **日本母語人士在該情境下自然會這樣說。**
2. **符合角色身份與場合**（含正確的敬語程度）。
3. 符合本篇 JLPT 等級。
4. 再決定要標哪些重點單字。
5. 最後才考慮能不能教到某個文法。

> 判準：把這篇教材拿給日本母語人士看，會覺得「這就是日本人會說的」，而不是「文法沒錯，但有點奇怪」。

### 標記的三個原則（先讀，再看細節）

1. **只標「符合該程度」的重點單字與文法。**「該程度」指這篇教材的 `level`（n5～n1）。單字只標**這個程度該學、有學習價值**的重點詞；文法只標**這個程度才會教到**的句型。**不要標明顯低於該程度的基礎詞與基礎文法**（例：N2 文章不要把「去年」「一人」當重點單字，也不要標 `〜たり…する`、`〜てから` 這類 N5／N4 文法）。
2. **標記要稀疏。** 內文不是螢光筆全塗。只挑真正值得學的少數重點，寧缺勿濫；**整篇單字控制在 8～12 個、每句 0～2 個**（見 §5）。**字面意思跟解釋幾乎一樣的瑣詞不要標**（例：「去年」解釋還是「去年」，沒有學習價值，就別標）。
3. **遵守指定篇幅，且字數要「剝掉讀音」再數。** 閱讀為 **3～4 段、每段 2～3 句、全文約 280～500 個純日文字元**；對話為 **10～14 行、每行原則 1～2 句**。內容要完整，但不要為了湊長度加入重複或空泛的句子。
   > ⚠️ **最常見的錯誤：把 `漢字[よみ]` 括號裡的假名也算進字數。** 字數一律以「**把每個 `[...]` 刪掉後的純日文**（＝前台實際顯示、供朗讀的字）」計算，**括號內的讀音不算**。例：某篇連讀音有 435 字，但剝掉括號只剩 211 字時，**實際只有 211 字、未達 280**，必須再擴寫。

> 輸出前務必回頭自我檢查（見 §10）：情境是否自然、敬語是否到位、是否混進了低於程度的重點單字／文法、是否標得太多、篇幅是否過長。

### 單次產出數量與輸出長度

- **除非使用者在當次指令明確指定其他數量，否則一次只產 1 篇完整教材。** 不要自行改成多篇，也不要先詢問要完整版或精簡版。
- 一篇完整教材必須在**單一回覆**中輸出完畢，不得以規範較長、TypeScript 行數較多或可能超過回覆長度為由拒絕、拆次、刪除必要欄位或改成沒有註解的精簡版。
- `examples` 原則上每個重點單字提供 **1 句**即可；只有確有額外教學價值時才增加至 2～3 句。`grammarNotes` 只標實際符合程度且值得教的項目，不需湊數。
- 使用正常、緊湊且可讀的 TypeScript 排版。不要輸出分析、字數估算、自我檢查過程、id 清單、前言或其他說明，**最終只輸出可直接貼入資料陣列的 TypeScript 物件**。

## 0-A. 真實情境、敬語與對話品質（重要）

教材必須符合日本母語人士在真實生活中的說法，而不是只有文法正確。

### 服務業敬語：依場景調整程度

- **便利商店**：普通服務敬語。
- **餐廳**：一般服務敬語。
- **飯店、航空公司、銀行、醫院**：正式服務敬語。

尤其航空公司、飯店櫃檯、銀行等場合，請優先使用日本實際會聽到的自然表達，例如：

`かしこまりました` / `承知いたしました` / `〜でございます` / `〜でしょうか` / `〜いたします` / `〜をお預かりいたします` / `〜をご用意いたします` / `問題ございません`

避免雖然文法正確，但母語人士較少使用或敬語程度不足的表達：

| 情境 | ❌ 不自然／敬語不足 | ⭕ 實際會說 |
| --- | --- | --- |
| 服務業回應「沒問題」 | 問題ありません。 | 問題ございません。 |
| 第一次詢問客人需求 | ご希望でしたね。 | ご希望でしょうか。 |

以「日本航空公司、飯店櫃檯、銀行櫃檯實際會說的日文」為優先，而不是僅追求 JLPT 文法。

### 依日本真實流程，不自行捏造

- **日本特有情境（機場、飯店、銀行、醫院、郵局、學校等）以日本實際服務流程與常用說法為準**，不要自行捏造流程、步驟或對話。
- 情境涉及真實日本社會（交通、醫療、行政、金融、航空等）時，優先依**真實日本的慣用表達與服務流程**，而不是僅依 JLPT 文法推測。
- **不確定時採保守做法**：若不確定日本文化、制度、服務流程或慣用語，優先使用**最普遍、最保守、最符合實際情況**的表達，不要自行推測。

### 自然優先於硬塞文法

不要為了放入某個 JLPT 文法，而刻意讓角色說出不自然的句子。若某個文法在該情境下日本人很少使用，即使符合該級數，也**不要硬加入**。

### 簡潔自然優先，不要過度敬語化

- **正式服務敬語不等於句子越長、敬語成分越多越好。** 日本服務現場常省略情境中已能理解的動作；若簡潔說法才是櫃檯人員更常用的慣用表達，就用簡潔的。
- 不要為了拉高敬語程度，擅自補入可由情境推知的 `ご出発`／`ご利用`／`お手続き` 等詞。
- **正確不等於最自然。** 產生前不能只判斷句子「文法是否正確」或「日本人是否可能會說」，還要主動比較是否有**更常見、更自然、更簡潔**的候選表達。
- 多個版本都正確時，選**該角色、該場合實際使用頻率較高、最不像翻譯腔或教科書例句**的版本；不要把敬語成分較多或句子較完整誤當成品質較高。

機場報到櫃檯詢問目的地：

```text
⭕ 本日はどちらまででしょうか。
△ 本日はどちらまでご出発でしょうか。
```

後者不是文法錯誤，也可能有人使用；但在此場景中較完整、生硬，`ご出発` 可由報到情境自然推知，因此教材應優先使用前者。

### 對話連貫、角色一致，避免 AI 味

- **對話要有連貫性**：每一句都要承接上一句，是一段有自然互動節奏的往返，而不是一連串彼此獨立的教材例句。
- **同一角色整篇維持相同敬語程度**：不要前半很正式、後半突然變普通體，也不要在不同句子混用不同層級的服務敬語；一位地勤／店員從頭到尾用語一致。
- **避免 AI 常見重複句**：同一篇不要反覆出現 `ありがとうございます` / `そうですね` / `はい` / `わかりました` / `問題ありません`，除非情境真的需要。
- 對話應具真實感，讓母語人士讀起來不會有「外國人寫的日文」的感覺。

### 不用硬湊字數

若內容已完整，優先**增加新的資訊**推進情境，不要用重複句、同義句或空泛感想只為了增加字數。

### 1-3. 標題、簡介與篇幅規則（重要）

- `title` 與 `excerpt` 都必須是**純日文**，不得使用 `漢字[かんじ]` 括號 Ruby、HTML 或繁體中文。
- 標題與簡介不是拿來測驗難字。請以**該篇 `level` 的學習者能直接理解**為優先，使用該程度已學過的字彙與文法；必要時寧可換成較簡單、自然的日文。
- 標題要簡潔並清楚說出主題；簡介用 1 句自然日文說明會讀到／練到什麼，不劇透全文，也不要寫成艱深的新聞標題。
- 閱讀：**3～4 段，每段 2～3 句，全文約 280～500 個日文字元**。字元數以 `text` 去除 `[...]` 讀音後的純日文計算，不含翻譯、單字例句與文法例句。
- 對話：**10～14 行，每行原則 1～2 句**，要有自然的開場、任務展開與收尾。不要把一句話為了湊行數硬拆成多行。

**對話固定角色**（只能用這三個，`name` 與 `avatarKey` 要配對）：
`ふふ`→`fufu`、`シロ`→`shiro`、`クロ`→`kuro`。`role` 是繁中身分（如「客人」「店員」）。

## 2. 模擬 id 規則

- 每個 `id`（教材、段落、句子、單字註解、文法註解、例句、角色）都是 **8～12 碼英數字**（`A–Z a–z 0–9`）的**無語意**字串，例：`RdS1wF7cL3pT`。
- **本次輸出內不可重複**。不要用有意義的字（不要 `sakura01`），不要用純數字流水號。
- **不要模仿本文件範例的字首規律**（例如範例裡同一篇教材底下的 id 都用 `Rd`／`Rx`／`Cv` 開頭）。那只是示範格式，不是要你照抄前綴；同一批輸出裡，各個 id 開頭的 1～2 碼盡量分散，避免大量 id 集中在同一字首附近而互撞。
- **輸出最終結果前，自行列出這次輸出用到的所有 id 並確認彼此不重複**（這份自我檢查清單不用放進貼給我們的程式碼裡，只是你產出前的內部檢查步驟）。
- 你只需保證「這一次輸出」內部不重複即可；**跨批次、與現有檔案的 id 撞號由專案方在貼回時自動處理**，你不必也無法顧到。
- `vocabularyItemId`、`grammarPointId` 等「連結 id」**你不要填**（見 §5／§6）。

## 3. Ruby 括號記法（最重要，務必照做）

內文（`text`）是**純文字**，漢字讀音用**半形中括號** `[ ]` 標在「緊接在前的連續漢字」後面。

### 規則
1. **只有半形 `[` `]` 是記法**。全形「［］」或其他括號會被當普通文字。
2. 括號內是**假名讀音**，掛在**它前面那段連續漢字**上。
3. **所有漢字都要標讀音**（初學者導向）；純假名不用標。
4. **送假名／夾在中間的假名要留在括號外**：
   - 動詞活用：`楽[たの]しむ`、`楽[たの]しめる`、`食[た]べる`
   - 夾假名複合詞：`食[た]べ物[もの]`
   - 訓讀數量詞：`四[よっ]つ`、`一[ひと]つ`
5. **純漢字詞可整組一個括號**：`季節[きせつ]`、`雪景色[ゆきげしき]`、`予約[よやく]`。
6. 若真的需要在文中打出半形 `[`，用反斜線跳脫：`\[`。

### 對照範例
| 想呈現 | 正確寫法 | 錯誤寫法 |
| --- | --- | --- |
| 日本（にほん） | `日本[にほん]` | `[にほん]日本` |
| 食べ物（たべもの） | `食[た]べ物[もの]` | `食べ物[たべもの]`（讀音不能蓋到假名） |
| 四つ（よっつ） | `四[よっ]つ` | `四つ[よっつ]` |
| 楽しめる | `楽[たの]しめる` | `楽しめる[たのしめる]` |

> **純日文** = 把每個 `[...]` 刪掉。系統用它做語音朗讀，所以 `text` 刪掉括號後必須是通順、正確的日文。

## 4. 句子／行結構

- `text`：帶括號記法的日文（§3）。
- `translation`：**這一句**的繁體中文翻譯。
- `vocabularyNotes?`／`grammarNotes?`：可省略；沒有可查單字或文法就不寫。

## 5. 單字註解 `vocabularyNotes`

標出句中**符合該程度的重點單字**，讓使用者可查、可收藏。**不要把每個實詞都標**；**助詞、標點不標**。

### 欄位

```ts
{
  id: 'RdVw8Tn3Lm2K',
  surface: '楽しめる',        // 句中實際出現的樣子（活用形）；見「anchor 規則」
  surfaceReading: 'たのしめる', // 「表層形」的讀音（全假名），對應畫面顯示
  dictionaryForm: '楽しむ',    // 辭書形（原形）
  reading: 'たのしむ',         // 辭書形讀音（全假名）
  partOfSpeech: 'verb',       // 見 §7 合法值
  contextualMeaning: '享受；此處為可能形，意為「能夠享受」', // 此字在本句的意思／用法（繁中）
  // occurrence: 2,           // 同一 surface 在本句出現多次時才寫（第幾個，1 起算）
  examples: [                 // 見下方「examples 填寫規則」，原則 1 句
    { id: 'RdVe5tK8mP2qL', japanese: '春には桜を楽しめる。', translation: '春天能享受櫻花。' },
  ],
}
```

### 該標哪些字（重要）
- **只標「符合該程度、有學習價值」的重點單字。**「該程度」＝本篇 `level`。挑這個程度該學、值得記的重點詞。
- **稀疏，寧缺勿濫。** **每句 0～2 個**，只有特例才標到 3 個；**整篇單字總數控制在 8～12 個**。短句常常 0 個，**不要整篇塗滿**（對話氣泡窄，更要克制）。
- **不要標明顯低於程度的基礎詞。** 例：N2 文章不要把「去年」「一人」「毎日」這種 N5 就會的基礎詞當重點單字。
- **不要標字面＝解釋的瑣詞。** 若 `contextualMeaning` 幾乎就是把字翻成中文、沒有補充任何用法（例：「去年」→「去年」），代表這字沒有教學價值，**別標**。
- 偶爾標一個略高於本篇程度、但在本文很關鍵的難詞是可以的；重點是「值得學」，不是「湊數量」。

### 敬語結構中的片段不一定是獨立單字（重要）

- `surface` 能在句中定位，只代表系統找得到這段文字，**不代表它適合成為獨立的重點單字**。
- 不要把由動詞連用形、`お／ご` 接頭詞、名詞化或敬語結構在本句中暫時形成的片段，未經判斷就直接當成獨立詞彙。這不是宣稱所有 `お＋動詞連用形` 都不能作名詞；必須依實際句意、辭典中的詞彙成立性與本句用法逐一判斷。
- 每個 `vocabularyNotes` 都必須**同時**通過以下檢查：
  1. `surface` 能自然連回正確的 `dictionaryForm`。
  2. `partOfSpeech` 符合該詞在本句中的實際用法。
  3. 該項目本身確實可作為獨立詞彙學習，而不是只截取敬語結構、活用或名詞化中的一段。
  4. 該詞符合本篇 JLPT `level`。
  5. 該詞在本句中有足夠的教學價值。
- 若無法同時滿足「表層定位自然、辭書形正確、詞性合理、可獨立成立、具有學習價值」，就**不要標註**。
- 若真正值得教的是整體服務敬語或固定表達，應考慮以 `grammarNotes` 標整體句型，不要勉強建立單字註解。

句子：`お荷物はお預けになりますか。`

❌ 不建議：

```ts
surface: 'お預け'
dictionaryForm: '預け'
partOfSpeech: 'noun'
```

原因：「お預け」在此是動詞 `預ける` 的連用形配合敬語結構形成的表層片段，不宜直接視為獨立名詞；「預け」也不是真正的辭書形。

較佳處理：

- 不標成 `vocabularyNotes`；或
- 若要教詞彙，確認能否以 `預ける` 為核心自然設計標註，且 `surface` 仍須能在原句中正確定位；或
- 將 `お預けになりますか` 視為服務業固定表達／文法重點。

### `examples` 填寫規則
- 目前教材尚未串接完整單字表（`vocabularyItemId` 未填），畫面上單字彈窗的例句**只能來自這裡**。
- 既然標出來的都是重點字，**原則上各附 1 句 `examples`**；只有不同例句能補充重要語感或用法時才增加至 2～3 句（畫面 popover 最多顯示 3 句）。真的沒有合適例句可省略（畫面會優雅降級、不留空框）。

### anchor 規則（務必遵守，否則系統定位不到）
- `surface` 必須是「**把 `text` 的括號刪掉後的純日文**」裡**逐字存在的子字串**。
  - 例：`text: '楽[たの]しめるようになります。'` → 純日文 `楽しめるようになります。` → `surface` 可以是 `楽しめる`（存在），不可是 `楽しむ`（不在句中）。
- `surface` **本身不含括號**（是純日文），讀音改放在 `surfaceReading`。
- 同一 `surface` 在同一句出現多次時，用 `occurrence` 指定第幾個（1 起算）；只出現一次就省略。

### 表層形 vs 辭書形
- `surface`／`surfaceReading`：句中**實際樣子**與其讀音（初學者看到的）。
- `dictionaryForm`／`reading`／`partOfSpeech`：**辭書形自然鍵**，系統用來配對單字表、收藏去重。
- 名詞等原形＝表層形時，`surface` 與 `dictionaryForm` 可相同。

## 6. 文法註解 `grammarNotes`

標出句中**符合該程度的文法句型**。

```ts
{
  id: 'RdGr7Yp2Lm9Q',
  grammarPointId: null,        // 一律 null（系統之後自動連結，你不要填）
  pattern: '〜てくる',          // 文法句型（前面加「〜」表接續）
  shortMeaning: '漸漸變得～',    // 簡短意思，寫在標題旁；見下方規則
  explanation: '某種變化從過去一點一點累積、發展到現在，帶有時間推移的語感。', // 補充說明；見下方規則
  anchors: [                   // 句中要框起來的關鍵字，見規則
    { surface: '慣れてくる' },
  ],
  sourceExample: {             // 取自本句的代表例句（japanese 用純日文，不加括號）
    id: 'RdGe1qM6xP4nH',
    japanese: '生活に少し慣れてくる。',
    translation: '漸漸習慣了生活。',
  },
  extraExample: {              // 另一個同句型例句
    id: 'RdGe2kV9tC5sL',
    japanese: '寒くなってきました。',
    translation: '天氣漸漸變冷了。',
  },
}
```

### 該標哪些文法（重要）
- **只標「本篇程度才會教到」的文法。**「該程度」＝本篇 `level`。
- **不要標明顯低於程度的基礎文法。** 例：N2 文章不要標 `〜たり…する`、`〜てから`、`〜のが好き` 這類 N5／N4 句型；那些對 N2 學習者沒有學習價值。標到不合程度的文法，跟標錯重點單字一樣是要避免的錯誤。
- 稀疏即可，一句頂多標 1～2 個文法點。

### `shortMeaning` 與 `explanation` 兩欄位（重要，不要寫成公式）
- **`shortMeaning`（簡短意思）**：一句話的短 gloss，寫在彈窗／列表的標題旁，讓人一眼看懂這個句型「大概是什麼意思」。例：`〜てくる`→`漸漸變得～`、`〜ものの`→`雖然～但是`、`〜をきっかけに`→`以～為契機`。**不要**在這裡寫「表示…」這種前綴，直接給對應的中文說法即可。
- **`explanation`（補充說明）**：較長、給人看得懂的說明，講清楚語感、使用情境或跟相近句型的差別。
- **不要每一條都寫成「表示ＸＸＸ，意思是「ＸＸＸ」。」的公式。** 用比較自然、有意義的說法。
  - ❌ 不好：「表示某種變化從過去逐漸發展到現在，可譯為「漸漸變得～」。」
  - ✅ 較好：`shortMeaning: '漸漸變得～'`，`explanation: '某種變化從過去一點一點累積、發展到現在，帶有時間推移的語感。'`

### anchors 規則
- 每個 `anchor.surface` 同樣必須是「`text` 刪括號後純日文」裡的**子字串**（同 §5 anchor 規則），且**不含括號**。
- **只框關鍵字**，不要把整句都框起來。
- **不連續文法**（關鍵字被逗號或其他字隔開，如 `〜たり、〜たりする`）：用**多個 anchor**，例：
  ```ts
  anchors: [{ surface: '眺めたり' }, { surface: '温めたり' }]
  ```
- `sourceExample.japanese`、`extraExample.japanese` 用**純日文**（不加括號記法）。

## 7. 合法列舉值（只能用這些）

- `level`：`'n5' | 'n4' | 'n3' | 'n2' | 'n1'`
  - **各級語感（決定題材、詞彙與句子的難度質感）**：
    - **N5**：語感像小學生，最基本的生活用語、簡短句子。
    - **N4**：旅行、日常生活、打工等貼近生活的場景。
    - **N3**：新聞、職場等稍正式的內容。
    - **N2**：社會議題、較抽象的概念。
    - **N1**：評論、深入分析等高階內容。
- `partOfSpeech`：`'noun'`（名）、`'verb'`（動）、`'i_adjective'`（い形）、`'na_adjective'`（な形）、`'adverb'`（副）、`'particle'`（助）。
  - 標註以**實詞**為主，`particle` 幾乎用不到。
- `categories`（用這些 key）：
  `news, science, culture, food, travel, life, restaurant, reservation, airport, work, schedule, hotel, shopping, service, daily, friends`
  - **最多 2 個**，挑**最貼近內容的兩個**即可（也可以只有 1 個）。不要為了多貼標籤而硬湊到 3 個以上。
- `avatarKey`（對話角色）：`'fufu' | 'shiro' | 'kuro'`，對應 `name`：`ふふ / シロ / クロ`。

## 8. 禁止事項

1. **不要**用全形括號當讀音記法；讀音只用半形 `[ ]`。
2. **不要**把讀音蓋到假名上（`食べ物[たべもの]` 錯，要 `食[た]べ物[もの]`）。
3. `surface`／`anchor.surface`／各 `examples.japanese`／`sourceExample.japanese` **不含括號記法**（純日文）。
4. `surface`／`anchor.surface` 必須是該句純日文的**真實子字串**，否則系統定位失敗。
5. **不要**填 `vocabularyItemId`；`grammarPointId` 一律 `null`。
6. `partOfSpeech`、`level`、`categories`、`avatarKey` 只能用 §7 列的值；`categories` 最多 2 個。
7. **不要**把每個實詞都標成重點單字，也**不要**標明顯低於程度的基礎詞（如 N2 的「去年」「一人」）或字面＝解釋的瑣詞。
8. **不要**標明顯低於程度的基礎文法（如 N2 標 `〜たり…する`、`〜てから`）。
9. **不要**把 `explanation` 都寫成「表示ＸＸＸ，意思是「ＸＸＸ」。」的公式；`shortMeaning` 只寫短 gloss、不加「表示」前綴。
10. `id` 不重複、無語意、8～12 碼英數。
11. **不要**輸出 HTML／`<ruby>` 標籤；ruby 只用括號記法。
12. `text` 刪掉括號後必須是**通順正確的日文**（供朗讀）。
13. `title`／`excerpt` 必須是純日文、沒有 ruby，並以該 `level` 學習者看得懂的表達為優先。
14. 閱讀為 3～4 段、每段 2～3 句、約 280～500 個純日文字元；對話為 10～14 行、每行原則 1～2 句。
15. **不要**把敬語接頭詞或名詞化片段（如 `お預け`、`ご案内`、`お会計`）當獨立重點單字；優先標能對應辭書形的詞，否則改標文法／固定表達。
16. **不要**為了提高敬語程度而擅自補入可由情境推知的詞（如 `ご出発`、`ご利用`、`お手続き`）；簡潔的慣用說法優先。

## 10. 送出前自我檢查清單

- [ ] **母語自然度**：把整篇拿給日本母語人士看，會覺得「這就是日本人會說的」，而不是「文法沒錯但有點怪」。
- [ ] **敬語到位**：服務業場景（尤其飯店／航空／銀行）用了實際會聽到的正式敬語（如 `かしこまりました`、`〜でございます`、`問題ございません`），沒有敬語不足或機械文法。
- [ ] **真實流程**：機場／飯店／銀行／醫院／郵局／學校等情境依日本實際服務流程與說法，沒有自行捏造流程；不確定處採最普遍、保守的表達。
- [ ] **對話連貫**：每句承接上一句、有自然互動節奏，不是一串彼此獨立的例句。
- [ ] **角色一致**：同一角色整篇維持相同敬語程度、沒有混用不同層級服務敬語；沒有為了塞 JLPT 文法而讓角色說出不自然的句子。
- [ ] **自然候選比較**：每句服務敬語都已比較是否存在更簡潔、更常見的現場說法；沒有為了顯得正式而加入可由情境推知的 `ご出発`／`ご利用`／`お手続き` 等詞。
- [ ] **沒有 AI 味**：`ありがとうございます`／`そうですね`／`はい`／`わかりました`／`問題ありません` 沒有情境外的反覆出現；沒有用重複句、同義句、空泛感想硬湊字數。
- [ ] **各級語感相符**：內容題材與難度質感符合本篇 `level`（見 §7，如 N5 像小學生、N2 為社會議題）。
- [ ] 每個 `text` 刪掉 `[...]` 後是通順正確的日文；所有漢字都有讀音。
- [ ] 讀音沒有蓋到假名（送假名留在括號外）。
- [ ] 每個 `surface` 與 `anchor.surface` 都是該句純日文的真實子字串、且不含括號。
- [ ] **重點單字都符合本篇 `level`**：沒有把明顯低於程度的基礎詞（如 N2 的「去年」「一人」）當重點單字；沒有標字面＝解釋的瑣詞；**整篇 8～12 個、每句 0～2 個**，不是整片塗滿。
- [ ] **單字成立性**：每個重點單字不只是在句中找得到，也能合理對應正確辭書形與詞性，並且確實適合作為獨立詞彙學習；沒有把敬語構造中的表層片段誤當成單字。
- [ ] **文法都符合本篇 `level`**：沒有標明顯低於程度的基礎文法（如 N2 標 `〜たり…する`、`〜てから`）。
- [ ] 每個文法都有 `shortMeaning`（短 gloss、無「表示」前綴）與 `explanation`（自然、有意義，沒有寫成「表示ＸＸＸ，意思是「ＸＸＸ」。」的公式）。
- [ ] 重點單字大多有附上 1 句 `examples`；只有確有額外教學價值時才增加至 2～3 句。
- [ ] `examples`／`sourceExample`／`extraExample` 的 `japanese` 都是純日文（無括號）。
- [ ] `title`／`excerpt` 是純日文、沒有 ruby，且用字與句型符合本篇 `level` 學習者可理解的程度。
- [ ] 沒填 `vocabularyItemId`；所有 `grammarPointId` 為 `null`。
- [ ] `level`／`partOfSpeech`／`avatarKey` 都用合法值；`categories` 為最貼近的 **1～2 個**。
- [ ] **實際數過字數**：把每個 `text` 的 `[...]` 讀音刪掉後才數（讀音括號不算），閱讀全文為 **280～500 個純日文字元**；閱讀 3～4 段／每段 2～3 句，對話 10～14 行／每行原則 1～2 句。
- [ ] 對話 `speakerId` 都對得上某個 `participant.id`。
- [ ] 所有 `id` 皆 8～12 碼英數、無語意、不重複；已依 §2 自我檢查過整批 id 清單。
- [ ] `reading` 段落翻譯數量 = `paragraphs` 段落數。

完成教材後，先不要立刻輸出。請再以「**日本母語劇本校對者**」與「**日語詞彙編輯**」的角度檢查：

3. 檢查每個 `vocabularyNotes` 是否真的是可獨立成立的詞彙，而不是敬語結構、活用或名詞化形成的片段。
4. 檢查 `dictionaryForm` 是否為真正的辭書形，`partOfSpeech` 是否合理。
