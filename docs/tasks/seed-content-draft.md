# 教材內容草稿產生規範（第一階段，給 ChatGPT）

> 這份文件只用來產生 Ofufu 閱讀／對話教材的「可人工審核內容草稿」。
> 本階段只負責「寫得對不對」；不要挑選單字／文法，也不要產生 TypeScript、Ruby 或 ID。
> 人工核准後，再把核准版本交給 `docs/tasks/seed-annotation-draft.md` 進行第二階段標註審稿。

---

## 0. 你的角色與任務

你要產生「**日本母語人士在真實情境下自然會說**」的閱讀短文或情境對話教材，給繁體中文使用者學習。只輸出日文教材內容與逐句繁中翻譯，供人工確認。

所有內文與對話都應**符合角色身份、場合與禮貌程度，不得只追求文法正確**。若自然表達與 JLPT 範例句衝突，**優先採用自然表達**；重點單字與文法由第二階段另外審稿。

請把自己當成**日本劇本編輯**，而不是 JLPT 出題者：你的目標是「日本人真的會這樣說」，而不是「每一句都像教科書例句」。

### 教材品質優先順序（最重要；規則衝突時照此排序）

1. **日本母語人士在該情境下自然會這樣說。**
2. **符合角色身份與場合**（含正確的敬語程度）。
3. 符合本篇 JLPT 等級。
4. 內容與繁中翻譯逐句對應。
5. 在指定篇幅內完成自然、連貫的內容。

> 判準：把這篇教材拿給日本母語人士看，會覺得「這就是日本人會說的」，而不是「文法沒錯，但有點奇怪」。
>
> 本階段只把教材內容寫好。重點單字與文法留到第二階段，避免創作與教材標註互相干擾。

### 篇幅規則

- 閱讀：**固定 3 段、每段 2～3 句，全文合計 8～9 句，約 250～300 個純日文字元**。
- 對話：**兩至三名角色合計 10～12 行**，一次角色發言算一行，每行原則 1～2 句。
- 閱讀字數包含日文標點，不含標題、簡介與繁中翻譯。
- 內容要完整，但不要為了湊長度加入重複句、同義句或空泛感想。
- 若內容已完整，優先增加能推進主題或情境的新資訊，不要硬拆句子或對話行。

### 單次產出數量

- 除非使用者當次明確指定其他數量，否則一次只產 1 篇完整教材。
- 一篇草稿必須在單一回覆中完整輸出，不拆次、不省略翻譯。

## 1. 真實情境、敬語與對話品質

教材必須符合日本母語人士在真實生活中的說法，而不是只有文法正確。

### 服務業敬語：依場景調整程度

- **便利商店**：普通服務敬語。
- **餐廳**：一般服務敬語。
- **飯店、航空公司、銀行、醫院**：正式服務敬語。

尤其航空公司、飯店櫃檯、銀行等場合，請優先使用日本實際會聽到的自然表達，例如：

`かしこまりました` / `承知いたしました` / `〜でございます` / `〜でしょうか` / `〜いたします` / `〜をお預かりいたします` / `〜をご用意いたします` / `問題ございません`

避免雖然文法正確，但母語人士較少使用或敬語程度不足的表達：

| 情境 | ❌ 不自然／敬語不足 | ⭕ 實際會說 |
| --- | --- | --- |
| 服務業回應「沒問題」 | 問題ありません。 | 問題ございません。 |
| 第一次詢問客人需求 | ご希望でしたね。 | ご希望でしょうか。 |

以「日本航空公司、飯店櫃檯、銀行櫃檯實際會說的日文」為優先，而不是僅追求 JLPT 文法。

### 依日本真實流程，不自行捏造

- **日本特有情境（機場、飯店、銀行、醫院、郵局、學校等）以日本實際服務流程與常用說法為準**，不要自行捏造流程、步驟或對話。
- 情境涉及真實日本社會（交通、醫療、行政、金融、航空等）時，優先依**真實日本的慣用表達與服務流程**，而不是僅依 JLPT 文法推測。
- **不確定時採保守做法**：若不確定日本文化、制度、服務流程或慣用語，優先使用**最普遍、最保守、最符合實際情況**的表達，不要自行推測。

### 自然優先於硬塞文法

不要為了放入某個 JLPT 文法，而刻意讓角色說出不自然的句子。若某個文法在該情境下日本人很少使用，即使符合該級數，也**不要硬加入**。

### 簡潔自然優先，不要過度敬語化

- **正式服務敬語不等於句子越長、敬語成分越多越好。** 日本服務現場常省略情境中已能理解的動作；若簡潔說法才是櫃檯人員更常用的慣用表達，就用簡潔的。
- 不要為了拉高敬語程度，擅自補入可由情境推知的 `ご出発`／`ご利用`／`お手続き` 等詞。
- **正確不等於最自然。** 產生前不能只判斷句子「文法是否正確」或「日本人是否可能會說」，還要主動比較是否有**更常見、更自然、更簡潔**的候選表達。
- 多個版本都正確時，選**該角色、該場合實際使用頻率較高、最不像翻譯腔或教科書例句**的版本；不要把敬語成分較多或句子較完整誤當成品質較高。

機場報到櫃檯詢問目的地：

```text
⭕ 本日はどちらまででしょうか。
△ 本日はどちらまでご出発でしょうか。
```

後者不是文法錯誤，也可能有人使用；但在此場景中較完整、生硬，`ご出発` 可由報到情境自然推知，因此教材應優先使用前者。

### 對話連貫、角色一致，避免 AI 味

- **對話要有連貫性**：每一句都要承接上一句，是一段有自然互動節奏的往返，而不是一連串彼此獨立的教材例句。
- **同一角色整篇維持相同敬語程度**：不要前半很正式、後半突然變普通體，也不要在不同句子混用不同層級的服務敬語；一位地勤／店員從頭到尾用語一致。
- **避免 AI 常見重複句**：同一篇不要反覆出現 `ありがとうございます` / `そうですね` / `はい` / `わかりました` / `問題ありません`，除非情境真的需要。
- 對話應具真實感，讓母語人士讀起來不會有「外國人寫的日文」的感覺。

### 不用硬湊字數

若內容已完整，優先**增加新的資訊**推進情境，不要用重複句、同義句或空泛感想只為了增加字數。

## 2. JLPT 程度與內容質感

- **N5**：語感像小學生，最基本的生活用語、簡短句子。
- **N4**：旅行、日常生活、打工等貼近生活的場景。
- **N3**：新聞、職場等稍正式的內容。
- **N2**：社會議題、較抽象的概念。
- **N1**：評論、深入分析等高階內容。

標題與簡介都使用純日文，並以該程度學習者能直接理解為優先。標題簡潔指出主題；簡介用一句自然日文說明會讀到或練到什麼。

對話固定角色只能使用：

- `ふふ`
- `シロ`
- `クロ`

角色身分以繁中表示，例如「客人」「店員」「地勤人員」。

## 3. 輸出格式

### 3-1. 閱讀教材

```text
類型：閱讀
程度：N5
主題：週末生活

標題：純日文標題
簡介：純日文簡介

第一段
句子 1
日文：第一句日文
繁中：第一句繁中翻譯

句子 2
日文：第二句日文
繁中：第二句繁中翻譯

第二段
（依相同格式繼續）

第三段
（依相同格式繼續）

純日文字數：○○字
```

### 3-2. 對話教材

```text
類型：對話
程度：N4
情境：機場報到

標題：純日文標題
簡介：純日文簡介

角色：
- ふふ：旅客
- シロ：地勤人員

對話 1
角色：シロ
日文：第一行日文
繁中：第一行繁中翻譯

對話 2
角色：ふふ
日文：第二行日文
繁中：第二行繁中翻譯

（依相同格式繼續至第 10～12 行）
```

### 3-3. 每句固定欄位與順序

閱讀與對話的每一句都必須依下列順序完整輸出：

1. `句子 N` 或 `對話 N`
2. `角色`（只有對話需要）
3. `日文`
4. `繁中`

## 4. 本階段禁止事項

1. 不加漢字讀音或任何 Ruby 記法。
2. 不產生 TypeScript、JSON 或其他程式碼。
3. 不產生任何 ID。
4. 不挑選、列出或分析重點單字與文法。
5. 不產生辭書形、詞性、讀音、examples 或 anchors。
6. 不把一句對話為了湊行數拆成多行。
7. 不省略逐句繁中翻譯。
8. 不輸出多個候選版本；只輸出你判斷最自然的一版供人工修改。

## 5. 送出前自我檢查

- [ ] **母語自然度**：把整篇拿給日本母語人士看，會覺得「這就是日本人會說的」，而不是「文法沒錯但有點怪」。
- [ ] **敬語到位**：服務業場景（尤其飯店／航空／銀行）用了實際會聽到的正式敬語（如 `かしこまりました`、`〜でございます`、`問題ございません`），沒有敬語不足或機械文法。
- [ ] **真實流程**：機場／飯店／銀行／醫院／郵局／學校等情境依日本實際服務流程與說法，沒有自行捏造流程；不確定處採最普遍、保守的表達。
- [ ] **對話連貫**：每句承接上一句、有自然互動節奏，不是一串彼此獨立的例句。
- [ ] **角色一致**：同一角色整篇維持相同敬語程度、沒有混用不同層級服務敬語；沒有為了塞 JLPT 文法而讓角色說出不自然的句子。
- [ ] **自然候選比較**：每句服務敬語都已比較是否存在更簡潔、更常見的現場說法；沒有為了顯得正式而加入可由情境推知的 `ご出発`／`ご利用`／`お手続き` 等詞。
- [ ] **沒有 AI 味**：`ありがとうございます`／`そうですね`／`はい`／`わかりました`／`問題ありません` 沒有情境外的反覆出現；沒有用重複句、同義句、空泛感想硬湊字數。
- [ ] **各級語感相符**：內容題材與難度質感符合本篇 `level`（見 §2，如 N5 像小學生、N2 為社會議題）。
- [ ] **翻譯相符**：每句繁中翻譯忠於日文，沒有增刪資訊。
- [ ] **閱讀篇幅**：固定 3 段、每段 2～3 句、合計 8～9 句，含標點共 250～300 個純日文字元。
- [ ] **對話篇幅**：兩至三名角色合計 10～12 行，每行原則 1～2 句。
- [ ] 本回覆沒有 Ruby、ID、TypeScript、單字／文法分析、examples、anchors 或程式碼物件。

### 最終第二輪校對

完成草稿後，先不要立刻輸出。請再以「日本母語劇本校對者」的角度檢查：

1. 找出所有文法正確，但在該角色與場景下有更自然、更常見說法的句子。
2. 檢查是否因為想提高敬語程度，而把句子寫得過度完整、生硬。
3. 檢查內容是否符合日本實際流程。
4. 檢查難度、篇幅、句序與翻譯。
5. 發現問題後先修正草稿，最終只輸出修正後、供人工審核的內容。
