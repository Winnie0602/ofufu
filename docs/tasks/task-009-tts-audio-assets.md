# Task 009：TTS 與教材音檔正式流程

## 狀態

`Backlog`（需求已記錄，尚未開始規劃或實作。）

## 需求來源

Task 008 已完成閱讀／對話教材的前端播放體驗，目前需要保留既有互動成果，並在後續階段將暫時的即時 TTS 驗證改為可正式部署的教材音檔流程。

本 Task 先記錄需求與現況，暫不決定 API、資料庫、R2 路徑、權限或批次處理方式。開始實作前需另行討論技術方案。

## Task 008 交接現況

- 閱讀教材支援整篇文章序列播放及單句播放。
- 對話教材支援逐句播放、閱讀模式自動播放及角色扮演逐句練習。
- 角色扮演練習會等待別人台詞播放完畢後前進，輪到使用者時停止並等待練說。
- 所有播放路徑共用 `useTtsAudio`，同一時間只管理一個播放中的音訊。
- 播放速度支援 0.75x、1x、1.25x、1.5x，播放途中修改速度會立即生效。
- 模式切換、角色切換、停止播放或離開頁面時，既有播放及練習流程會停止。
- 前端教材目前使用 TypeScript mock data，尚未串接正式教材 API 或資料庫。
- 目前 `/api/tts` 是 Google Cloud Text-to-Speech 的實驗性 server route，接受文字後即時合成並回傳音訊。
- 公開部署環境尚未具備正式的音檔存取控制、快取、成本保護及 Audio Asset 流程。
- 在正式保護完成以前，公開部署應維持 TTS 停用，避免任意請求觸發付費合成。

## 產品需求

- 閱讀與對話教材需保留 Task 008 已完成的所有播放互動與播放速度功能。
- 正式教材句子應能對應到穩定、可重複使用的音檔。
- 同一份教材文字不應因使用者重複播放而反覆產生相同語音。
- 一般使用者播放教材時，不應能提交任意文字要求系統產生新語音。
- 公開播放行為與產生新音檔的能力必須分開管理。
- 未授權使用者不得觸發會產生成本的新語音。
- 音檔尚未準備、產生失敗或無法播放時，前端需有可理解且不破壞學習流程的狀態。
- 閱讀序列播放、對話序列播放及角色扮演練習需能處理缺少部分音檔的情況。
- 未來教材文字修改後，不可繼續誤用與舊文字不一致的音檔。
- 未來接上正式資料庫與教材 API 時，Task 008 的前端播放介面不應大幅重寫。

## 安全與成本需求

- 公開環境不能暴露可任意使用的付費 TTS 入口。
- 系統需能限制或停止異常請求，並具備緊急停用語音產生的能力。
- TTS 使用量、錯誤與成本風險需可被觀察。
- 音檔的重複產生、無限新增與無效資料需受到控制。
- 正式憑證與秘密值只能存在伺服器端，不得進入前端、mock data、版本控制或公開回應。

## 與目前開發階段的關係

- 本 Task 可以在正式 MongoDB Schema 與教材 API 完成前進行需求驗證。
- 現有 mock data 的教材、句子與對話行 ID 可作為前端流程驗證依據，但不代表正式資料庫結構已定案。
- `docs/schema.md` 仍是未來草案，不作為本 Task 必須提前建立資料庫的理由。
- 本 Task 不應阻塞其他教材頁、批次補資料或 UI 工作；開始時間由後續優先順序決定。

## Out of Scope（本次需求備忘）

- R2 object key、bucket 與快取策略。
- Google TTS voice、格式、音質與 provider 選擇。
- 認證、授權及 rate limit 的具體實作。
- MongoDB collection、index 與 migration。
- 管理員操作介面與批次工具設計。
- AI 產生教材與 resolver 流程。
- 部署平台與環境變數設定步驟。

## 後續開始前需確認

- Task 009 是否只做技術驗證，或包含可正式部署的完整流程。
- dev 網站是否維持私人使用，或需要讓其他測試者存取。
- 音檔應在教材發布前準備完成，還是允許其他受控的產生時機。
- 閱讀、對話以外的單字、文法、測驗與歌曲是否同時納入。
- 音檔缺漏時，各種播放與角色扮演流程預期如何降級。
- 正式 TTS 與 R2 是否維持同一 Task，或拆成數個較小 Task。
