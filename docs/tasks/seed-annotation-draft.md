# 教材重點標註審稿規範（第二階段，給 ChatGPT）

## 使用方式：請先完整閱讀，再分析核准內容

請分析本訊息最下方「第一階段核准內容」，逐句提出真正符合本篇 JLPT 程度、具有學習價值的候選重點單字與文法。

這可能是一個全新的 session。**不要假設你記得第一階段對話，也不要依賴本訊息以外的內容。** 最下方的核准內容是唯一教材來源，本文件是唯一標註規範。

你的任務只有「挑選值得教的重點」，不是重新創作或產生程式資料：

1. 不得修改標題、簡介、角色、日文、繁中翻譯、段落、句序或對話行。
2. 不加 Ruby、ID、examples、TypeScript、`vocabularyNotes` 或 `grammarNotes` 物件。
3. 不要求每句一定要有標註；沒有值得教的項目就明寫 `無`。
4. 不為了達到數量而標低程度基礎詞、基礎文法、普通詞組或字面＝解釋的瑣詞。
5. 若發現核准內容本身疑似有錯，只能列在「需要回到第一階段確認」中，不得自行改寫。

---

## 0. 標註品質優先順序

1. 符合本篇 JLPT `level`。
2. 在本文情境中真的具有教學價值。
3. 表層形或文法範圍能在原句逐字定位。
4. 辭書形、讀音、詞性及文法判斷正確。
5. 標記稀疏、寧缺勿濫。

> 數量是上限參考，不是最低要求。只有兩個值得教的詞就只列兩個；沒有值得教的文法就寫 `無`。

### 建議上限

- 閱讀：重點單字通常 3～8 個，上限 10 個；重點文法通常 1～4 個。
- 對話：重點單字通常 2～6 個，上限 8 個；重點文法通常 1～4 個。
- 每句／每行重點單字 0～2 個，文法 0～1 個為原則；不需湊滿。

---

## 1. 重點單字規則

- 只列符合本篇程度、值得學習的重點詞。
- 不列明顯低於程度的基礎詞。例如 N4 不需要因句中出現就標 `どちら`、`お願いします`、`重さ` 等基礎或字面型詞彙。
- 不列「本句意思只是把詞翻成中文」且沒有額外用法價值的瑣詞。
- 偶爾可保留一個略高於程度、但對本文情境非常關鍵的詞；必須在「選入理由」說明。
- `表層形` 必須逐字存在於該句日文；活用形不可直接拿辭書形冒充表層形。
- 表層形重複時要註明第幾次出現。
- 必須提供真正的辭書形與辭書形讀音。
- 不把敬語接頭詞、動詞連用形、名詞化或敬語結構中的片段誤當成獨立單字。
- 若真正值得教的是完整服務敬語或固定表達，優先判斷為文法／表達，不同時重複標成單字。

### 合法詞性

候選單字只能使用未來 TypeScript 可接受的詞性：

- `noun`：名詞
- `verb`：動詞
- `i_adjective`：い形容詞
- `na_adjective`：な形容詞
- `adverb`：副詞
- `particle`：助詞，原則上不作重點單字

若某個詞的正確詞性不在清單中，例如代名詞，**不要硬改成 `noun`**。通常應不列為重點；若確實有教學必要，放入「需要人工確認」。

### 單字輸出格式

不需在第二階段重複列出表層形讀音；第三階段會依核准原文補上。人工審核使用以下精簡格式：

```text
重點單字：
- 預けたい → 預ける（あずける）
  詞性：verb
  本句意思：想托運
  選入理由：機場報到常用，符合 N4 旅行情境
```

若同一表層形重複：

```text
  出現次數：第 2 次
```

## 2. 重點文法規則

- 只列本篇程度才值得教的文法。
- 不列明顯低於程度的基礎文法。例如 N4 對話通常不需標 `〜たいです`、`〜まで` 等更基礎的項目。
- 不把普通詞組、單純搭配或整句語意誤判成文法。
- 不為了塞入指定文法而修改核准內容。
- `句中範圍` 必須逐字存在於原句，只框真正承載文法功能的部分，不預設把整句都框起來。
- 不連續文法可以列出多個句中範圍。
- `簡短意思` 直接寫繁中 gloss，不加公式化的「表示」前綴。
- `補充說明` 說明語感、使用場合或重要差異，不重複簡短意思。

### 文法輸出格式

```text
重點文法：
- 句型：〜でしょうか
  句中範圍：でしょうか
  簡短意思：禮貌地詢問
  補充說明：比直接使用疑問句更柔和，常見於服務場合。
  選入理由：符合 N4 服務情境，具有實際溝通價值
```

不連續文法：

```text
  句中範圍：
  - 遊んだり
  - 走ったり
```

## 3. 統一輸出格式

完整保留第一階段的教材 metadata 與逐句內容，並在每句正下方加入重點單字及重點文法。

閱讀每句：

```text
句子 1
日文：核准日文
繁中：核准繁中
重點單字：無
重點文法：無
```

對話每行：

```text
對話 1
角色：シロ
日文：核准日文
繁中：核准繁中
重點單字：無
重點文法：無
```

- 欄位順序固定為：編號、角色（對話限定）、日文、繁中、重點單字、重點文法。
- 每句都必須保留兩個重點欄位，沒有項目時明寫 `無`。
- 標註只能放在所屬句子下方，不得集中在全文末尾，也不得跨句搬移。
- 完成全部句子後，可另外輸出「需要回到第一階段確認」；沒有疑問時寫 `無`。

## 4. 人工核准規則

- 專案方可刪除候選項目、修正欄位或補上遺漏項目。
- 人工核准後，每句保留下來的標註就是第三階段唯一允許建立的 notes。
- 被刪除的項目不得在第三階段重新出現。
- 寫 `無` 的欄位，第三階段不得自行補標。
- 人工核准時若修改教材原文，必須回到第一階段重新確認完整內容，再重新執行本階段。
