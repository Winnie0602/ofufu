## 每份教材內文的共用欄位需求

所有含日文內文的教材（文章、對話等）在資料層都要能提供：

1. **Ruby 讀音**：漢字上方假名，可由使用者全域開關顯示／隱藏。
2. **全日文純文字**：不含任何標記的完整日文，供 TTS、整篇閱讀、單句學習與內容遮罩使用。
3. **每句繁中意思**：逐句對照翻譯。
4. **整段／整篇繁中意思**：段落或全文層級的翻譯。

現有型別（`app/types/material.ts` 的 `MaterialTextSegment`、`ReadingSentence`、`ConversationLine` 等）方向正確，但需依下列策略調整「內容的 authoring 與身分解析」。

## Ruby 策略：輸入格式與顯示格式分離

- **顯示（render）維持結構化 token**：由 `MaterialTextSegment` / `parts[]` 產生 `<ruby>`，永遠不使用 `v-html`，不從 DOM 重組教材。`RubyText.vue` 現有描述方式保留。
- **輸入／儲存（authoring）改用精簡的括號 furigana 記法**，例如：

  ```text
  日本[にほん]には四[よっ]つの季節[きせつ]があり、それぞれの景色[けしき]を楽[たの]しめます。
  ```

  括號內讀音掛在「緊接在前的漢字連續段」；混合如「食べ物」寫成 `食[た]べ物[もの]`。
- **由 parser 將括號記法轉成現有 token 結構**（`parts[]`）。好處：
  - AI 與管理員只需輸出／編輯易讀的字串，不必手寫冗長的 segment JSON，消除「Ruby 像用程式硬拼」的感受。
  - 「全日文純文字」只要把括號剝除即可得到，TTS 使用此純文字。
- 不嘗試用「純日文 + 讀音字串」在前端自動對齊 furigana（alignment 是難題，AI 生成易出錯）；讀音對齊由產生階段以括號記法明確表達。

## 單字身分與去重（核心需求）

### 目標

使用者在閱讀頁收藏「食べた」、在單字頁收藏「食べる」，收藏區**只能出現一筆「食べる」**，且顯示的是**單字列表頁的完整單字資訊**，而不是閱讀頁較精簡的上下文註解。

### 身分：代理鍵 (surrogate id) 與自然鍵 (natural key) 的分工

- **`VocabularyItem`（單字列表頁的完整條目）本身就是詞條身分**，不另建獨立 lexeme 資料表。
- **PK（被參照的身分）＝穩定的代理鍵 (surrogate id)**：每筆單字有一個沒有語意、固定不變的 `id`（模擬 nanoid，如 `Vb7Kd2mNq9Xa`）。收藏、出現位置一律參照此 `id`。
  - 不用「羅馬拼音 slug」（如 `taberu`）或自然鍵字串當 PK：自然鍵有語意、**可能被修改**（改讀音、改詞性），一旦當 PK 被改，所有參照都會斷。代理鍵永遠不變才適合被參照。
  - 前端 mock 的 `id` 就是「未來後端 PK 的替身」，因此格式採 opaque 模擬 nanoid，之後接後端可無痛對接；前端不自行產生正式 PK，接後端後改用 API 回傳的 id。
- **自然鍵（配對／去重用，不是 PK）**：

  ```text
  自然鍵 = (dictionaryForm 辭書形, reading 讀音, partOfSpeech 詞性)
  ```

  用途是「由活用形找到辭書形條目、確保不重複」；資料庫層以此三欄建 **unique index**（非 PK）。

### 參照優先：教材內文的單字註解

- **教材內文的單字註解只是「出現位置（occurrence）＋上下文覆寫」，不重複保存完整單字資料**。至少保存：
  - `id`：此出現位置的固定模擬 nanoid（代理鍵）。
  - `surface`：實際出現的活用形（例：食べた）。
  - `surfaceReading`：**表層形自己的讀音**（例：楽しめる→たのしめる），與辭書形讀音不同、僅供畫面顯示，不用於配對。初學者看到的是表層形，讀音也該對應表層形，不能只給辭書形讀音。
  - `dictionaryForm`（辭書形）＋ `reading`（辭書形讀音）＋ `partOfSpeech`：配對自然鍵，非畫面主要顯示讀音。
  - `contextualMeaning?`：此字在**本段的意思／用法**（單字表沒有的、專屬本文的資訊）。
  - `vocabularyItemId`：**不由人手填**，由 resolver 依自然鍵解析後填入（見下）。
- 完整讀音、詞性、活用、例句、通用意思等一律由 `vocabularyItemId` 到單字表查得，不內嵌在教材註解。
- **收藏儲存 `vocabularyItemId`**（代理鍵）。因此「食べた」「食べる」都解析到同一條單字 `id`，天然去重；收藏區以該身分渲染單字表完整條目。

### Popover 顯示規則（精簡；配對只做去重）

- 教材內文的單字 Popover 走「輕量快速查看」，只顯示本文相關資訊：
  - 表層形（使用者點的字）＋詞性 badge（沿用單字列表頁樣式）。
  - 表層形自己的讀音 `surfaceReading`（永遠顯示，不是辭書形讀音）。
  - 「解釋」區塊：`contextualMeaning`「此字在本段的用法／意思」。
  - 「辭書形」區塊：**只在表層形是活用形時才顯示**（`surface !== dictionaryForm`），內容為 `dictionaryForm`／`reading`，方便查字典。
  - 「本篇例句」區塊：保留這篇教材依目前情境提供的例句；沒有時明確顯示目前沒有本篇例句。
  - 「單字教材例句」區塊：配對成功時另外顯示單字教材的例句，與本篇例句分區呈現。
  - 配對成功時以低干擾文字標示已收錄於單字教材；表層形是活用形時，顯示配對到的辭書形。
  - 兩個來源的日文完全相同時，以本篇例句為主並從單字教材例句去重。
  - 播放與收藏 UI。
- 「解釋」「辭書形」「本篇例句」使用灰色標籤（`badge-soft badge-neutral`），「單字教材例句」使用既有 primary 淡色標籤；區塊之間用留白分隔，不用分隔線。
- **不在 Popover 攤開單字表的通用意思／完整活用**；那屬於「收藏單字區」與單字列表頁的職責。
- **配對（resolver）在收藏時做去重**：按收藏時以辭書形自然鍵算出 `favoriteVocabularyKey`，讓同字不同活用形收斂成同一筆；Popover 只用配對結果顯示收錄狀態與例句來源，不攤開完整單字資料。
- 收藏單字區（未來會員 Task）用單字列表呈現：已配對→展開單字表完整資訊；未配對→顯示註解的簡易資訊（即未來待審核草稿單字的狀態）。
- 一律保留讀音與繁中意思，服務初學者；不做成「只有日文」。

> 現有 `MaterialVocabularyNote` 內嵌了 surface／reading／contextualMeaning／examples 與人工填的 `lexemeId`，屬於「自我完備」而非純參照，是造成重複與資訊不完整的根源，應往「參照優先＋自然鍵解析」調整。此方向與 `docs/schema.md` 的 `VocabularyOccurrence`（vocabularyItemId + segmentId + surface + contextualMeaning）一致。

## 文法連結

- 文法以穩定的 `pattern`／slug 作為身分鍵（例：`~ようになる`）。
- 教材內文法註解保存 `shortMeaning`（短 gloss，寫在標題旁，例：`〜てくる`→「漸漸變得～」）、`explanation`（給人看的補充說明，避免「表示ＸＸＸ，意思是「ＸＸＸ」。」的公式）與本文／其他例句，並以 nullable `grammarPointId` 連到完整文法頁。
- 產生流程輸出 pattern；resolver 若在文法教材找到對應 pattern 就連結 `/grammar/[id]`，找不到則建立待審核的草稿文法點。文法頁尚未建立時，前端維持「規劃中／停用」入口，不導向不存在的 route。

## 互動需求

- 每一句的重點單字都可滑過（hover）快速查看，點擊可看該單字在本段的用法、意思與更多例句。
- 單字：主要用途是「收藏後於收藏區看到單字表完整資訊」；目前不建立單字詳情頁，只有列表頁與收藏區。
- 文法：**點選後開一個與單字同版型的 popover**（`shortMeaning`＋`explanation`＋本文／其他例句＋「查看完整文法」入口），不再滑到頁尾；頁尾仍保留一份可展開的文法列表供整篇瀏覽。

## AI 產生內容與自動配對流程（重點）

**不採用「先產全部單字再限制 AI 只能用其中 20 個寫文章」，也不要求管理員手動為每個單字配對 ID。** 這是一個「照合／解析」問題，正解是**讓 AI 與人都不需要複製 ID**：

```text
AI 自由產生文章／對話
  └ 對每個標註單字輸出：辭書形 + 讀音 + 詞性 + 本段意思（不需 ID；AI 本就在做形態分析）
  └ 對每個標註文法輸出：pattern + 本文短解釋 + 例句
        ↓
Resolver（build 腳本或 import 時的後端）
  └ 以 (辭書形, 讀音, 詞性) 到 vocabulary_items 查對
        ├ 找到 → 自動填入 vocabularyItemId（配對完成）
        └ 找不到 → 自動建立待審核的草稿單字並連上（不留 dangling）
  └ 以 pattern 到文法教材查對，找不到則建立草稿文法點
        ↓
管理員只審核「新建立或有歧義的候選」，而非逐字配對
```

此流程的效果：

- **順序自由**：先產文章或先產單字都可行。
- **不會有未配對的破洞**：未命中的單字會變成草稿單字，收藏後仍能解析到完整條目（草稿條目初期資訊較少，待管理員／AI 補齊）。
- **管理員工作量從「全部配對」縮小為「審核少量候選」**。
- AI 不被「只能用 20 個字」限制，可自然寫作。

括號 Ruby 記法、單字辭書形、文法 pattern 都是 AI 既有能力可直接輸出的內容，額外負擔極低。

### 標題、簡介與教材篇幅

- 文章與對話的 `title`、`excerpt` 一律使用**純日文**，不加入括號 Ruby 或 HTML。
- 標題與簡介以該篇 `level` 的學習者能理解為優先，不刻意使用高於程度的生字或艱深句型；標題簡潔點出主題，簡介以一句自然日文說明內容。
- 閱讀教材為 **固定 3 段、每段 2～3 句、合計 8～9 句、全文約 250～300 個純日文字元（包含日文標點）**。
- 對話教材為 **10～12 行、每行原則 1～2 句**，內容需具備自然的開場、任務展開與收尾。

## 教材內文的單字與文法標記策略（符合程度、稀疏）

> **策略調整（取代原「featured 兩層」設計）**：原本讓 AI「廣泛標實詞＋少數 `featured` 主打」，實測會把「去年」「一人」這種明顯低於程度、且解釋＝字面的瑣詞也標成可收藏字，畫面吵、學習價值低。改為**只標「符合該篇程度、有學習價值」的少數重點**，不再分兩層、不再追求「廣覆蓋可收藏」。`featured` 欄位已移除。

### 單層：符合程度的重點單字（一律淡粉底）

- 每個單字標註就是「本篇的重點單字」，沒有主打／一般之分；查字模式開啟時**一律淡粉底色**標記，可點、可收藏；頁尾「重點單字」列出全部。
- **只標符合該篇 `level` 的重點單字**，稀疏、寧缺勿濫：
  - 不標明顯低於程度的基礎詞（N2 文章不標「去年」「一人」）。
  - 不標「字面＝解釋」的瑣詞（`contextualMeaning` 只是把字翻成中文、沒有補充用法）。
  - 偶爾標一個略高於本篇程度、但在本文很關鍵的難詞是可以的；判準是「值得學」，不是「湊數量」。
- 助詞、標點不進標註陣列；標記整體要克制，不是整片螢光筆。

### 文法標記與查字模式一致

- 文法標註同樣**只標符合該篇 `level` 的句型**（N2 不標 `〜たり…する`、`〜てから` 這類 N4／N5 文法）。
- 文法在內文以 **primary 淡底色**（非底線、非按鈕）標記，與單字同機制（底色只套底排文字、furigana 浮在外）；點擊開 popover（見「互動需求」）。
- **內文單字與文法都只在查字模式開啟時標記**；關閉時內文為乾淨純文字（單字與文法皆不標）。

### 覆蓋率在「生成時」決定，不在「執行時」

- 由 AI 生成文章時**一次輸出所有標註**（辭書形／讀音／詞性／本段意思），並自我檢查標到的都是符合程度的重點；AI 生成當下本就在做形態分析，額外成本低。
- **執行時不做 NLP、不查外部字典、不即時配對**。`vocabularyItemId` 由 resolver 於 import／build 時填入（見上節與 AI 流程）。
- 只有想做「使用者拖選任意字段、連 AI 沒標的字也要查」時才需要 runtime tokenizer；那是遙遠的 nice-to-have，**現階段不做**。

### 例句來源（分區顯示，不互相覆蓋）

1. 標註自帶的 `examples[]` 是**本篇例句**，保留教材情境。
2. 配對到單字表時，由詳情 API 另外提供 `vocabularyExamples[]` 作為**單字教材例句**。
3. 兩個來源的日文完全相同時，保留本篇例句並從單字教材例句移除重複句。
4. 沒有本篇例句時明確顯示空狀態；未配對時不顯示單字教材例句區塊。

### occurrence（同句消歧）

- 標註以「表層形字串 anchor」定位；同一表層形在一句出現多次時，用 `occurrence`（本句第幾個）指定要標哪一個。
- 可省略、預設為 1（唯一出現）；只有重複字才明寫 `occurrence: 2`。

## 閱讀／對話內文互動控制（Task 008 現行設計）

> 閱讀／對話模式採 Tab 互動語意並沿用原本紅色分段按鈕外觀，字級固定 16px。桌面將 Tabs、模式設定、播放速度與自動播放放在同一排；隱藏設定使用依內容寬度收合的 `neutral-100` 小圓角底。手機在 Tabs 下方放滿寬 `neutral-100` 模式設定，播放與閱讀輔助設定則移至教材內容前。模式設定切換時只做淡入與微幅下滑，避免下方教材上下跳動。以下皆為顯示層開關，不需要任何新資料欄位。
>
> 常駐開關的畫面短標籤使用「重點單字/文法」與「假名」；手機維持同一排且字級 12px，自動播放文字為 13px。
>
> 「隱藏整篇／隱藏日文／隱藏中文」使用眼睛 icon＋文字的無框、無底色按鈕；隱藏狀態使用 error 色提示。角色選擇仍使用單選按鈕。
>
> 手機教材控制使用共用 `StudyMobileControls.vue` 接上真實播放與顯示狀態。閱讀頁放在內文上方的 `neutral-50` 小圓角區；對話頁放在粉色對話容器內、第一句上方，並保留額外底部間距。

### 軸的拆分

- **版面（互斥，2 選 1）**：整篇閱讀 / 單句學習。
  - 取代 v1 的「中日對照／僅顯示日文／單句學習」。**移除「僅顯示日文」**：翻譯統一放在整篇日文下方、離閱讀位置很遠，遮它沒有意義；整篇模式上半部本就是純日文。
- **「顯示重點單字/文法」開關（獨立開關，放「顯示假名」開關左側；原名「查字模式」）**：
  - 關：內文為**乾淨純文字**，單字與文法皆不標。
  - 開：標出**符合程度的重點單字（淡粉底）與文法（primary 淡底）**，背景高度僅貼合字身；兩者皆可點開 popover。這是**手機版的可點性提示**（手機無 hover，靠此開關揭露）。
  - 與版面正交：整篇、單句下都能開。
- **假名（獨立開關）**：沿用。
- **播放速度（Select）**：沿用。

### 整篇閱讀：自動播放／隱藏整篇

- 播放速度與「自動播放文章」固定維持同一排，順序為播放速度在左、自動播放在右；整篇模式面板放「隱藏整篇」。隱藏後在日文原文上蓋一層**模糊／馬賽克遮罩**，配合播放專注練聽力。
- 遮罩與播放**各自獨立**（可先遮再播）；遮罩狀態下字的可點性無意義（本就是專注聽力），屬正常。

### 單句學習：全域隱藏日文／中文

- 單句模式面板放「隱藏日文／隱藏中文」兩個全域按鈕，可各自獨立遮蔽：
  - 遮中文 → 先讀日文、想不出再翻開（挑戰理解）。
  - 遮日文 → 由中文回想日文（挑戰產出）。
- 每張句卡左側不放逐句 eye；全域隱藏後，仍可直接點擊該句被模糊的日文或中文個別掀開。
- 預設兩者皆顯示。

## 對話頁互動模型（下一版方向）

> 對話頁與閱讀頁共用 Tabs、常駐設定與展開動畫，但模式專屬控制不同。對話天生就是一句一氣泡，頂部學習軸為「閱讀模式／角色扮演」。

### 資料

- 沿用閱讀的 note 結構（`surfaceReading`、辭書形自然鍵、例句優先序、`occurrence` 全部相同）。
- 對話行沿用現有 `speakerId` 連到 `participants`；角色扮演直接依此判斷台詞歸屬，不新增 `speakerRole`。
- 對話結構**比文章扁平**：material → lines[]，無 paragraph 層。
- **氣泡窄 → 重點標記要更稀疏**（每句頂多 1~2 個、短句常為 0），避免窄框內整排底色。
- 對話口語縮約多（だ／じゃない／〜ちゃう…），surface 與辭書形分歧更常見，正好大量用到 `surfaceReading` ＋「辭書形」區塊。

### 學習模式（頂部紅色分段 Tabs，二選一）

| 選項 | 畫面與行為 |
| --- | --- |
| 閱讀模式 | 播放速度與自動播放對話同排，順序為播放速度在左、自動播放在右；展開面板放隱藏日文與隱藏中文，兩者彼此獨立 |
| 角色扮演 | 播放控制順序同閱讀模式；展開面板放「你扮演」角色按鈕，只模糊該角色的日文，中文及其他角色台詞正常顯示 |

- 模式切換沿用原本 FlyonUI Join／Button 的紅色分段外觀，但使用 Tab 語意並由 Vue 管理狀態。
- 切換模式時停止正在進行的序列播放。
- 所有模糊內容都可直接點擊掀開；氣泡上不增加逐句 eye，避免重複控制。
- 角色扮演的自動播放跳過所選角色，只播放其他角色；所選角色仍保留逐句播放按鈕供核對。

### 其餘開關（同閱讀）

- **「顯示重點單字/文法」**（放假名左側）：關＝內文純文字（單字與文法皆不標）；開＝重點單字淡粉底、文法 primary 淡底，皆可點開 popover。
- **假名**、**播放速度**：沿用。
- **閱讀模式內容遮罩**：日文與中文各自一個開關，因此可組合成全部顯示、只遮中文、只遮日文或全部遮住；全部遮住可配合自動播放做純聽力練習。

### 遮蔽機制：一律用模糊遮罩，不用 display:none（閱讀／對話共用原則）

- 所有「藏日文／藏中文／聽力遮罩」都用**一塊模糊（馬賽克）遮罩蓋在上面**、**點一下可掀開核對**，**不直接 `hidden`／移除**。
- 原因：(1) 直接移除不好看、且造成版面跳動（reflow）；(2) 模糊 ＋ 掀開＝天然的「先自我挑戰、再核對答案」互動。

### 角色扮演模式

- **概念**：使用者選一個角色（A/B）扮演，該角色的日文用模糊遮罩蓋住（換你說），另一角色照常播音。對話教材專屬，單字／文章做不到。
- **精簡版（本版）**：依現有 `speakerId` 過濾，只遮所選角色的日文、可掀開核對；序列播放跳過該角色。純 UI、無新教材欄位。
- **完整版（資料齊全後再做）**：真正輪流對話——播對方 → 停頓等你說 →（可選）播你的角色當參考 → 繼續，甚至加錄音。音訊輪替與停頓較費工，延後。
