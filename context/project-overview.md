## 產品介紹

Ofufu 是全方位日文學習平台。產品從原本以歌曲與全站播放器為核心的網站，轉型為以多種教材和學習行為為核心的平台。

歌曲會保留，但只是六種教材之一。一般教材不應依賴 YouTube 或歌曲播放狀態。

## 解決的問題

日文學習資源經常分散在單字、文章、文法、歌曲和測驗工具中，使用者不容易在同一處持續學習與複習。Ofufu 希望提供繁體中文輔助、分級教材、聲音、收藏與學習紀錄，降低使用者在不同工具間切換的成本。

## 目標使用者

- 以繁體中文閱讀的日文學習者。
- 程度涵蓋第一次接觸日文的初學者至 JLPT N1。
- 希望依照程度找到適合教材。
- 需要日文發音、繁中解釋、測驗與複習輔助。

## 六大教材類型

1. 單字：依 JLPT 程度瀏覽，以 Ruby 顯示讀音，並提供活用、意思、詞性、例句、發音與收藏操作。
2. 文章：分級閱讀、逐句理解、翻譯、單字與音檔。
3. 對話：情境式角色對話、逐句翻譯、單字與角色聲音。
4. 歌曲：歌曲頁內播放、歌詞、翻譯與語言學習內容。
5. 文法：分級文法說明、例句、發音與練習。
6. 測驗：聽力、閱讀、讀音、單字及句子重組等題型；音訊來自教材或題目 Audio Asset，不依賴 YouTube。

## 會員價值

- 設定日文程度。
- 收藏教材與單字。
- 保存學習進度及測驗結果。
- 複習錯題。
- 跨裝置接續學習。

會員功能不是目前切版優先項目，但教材資料與使用者行為必須保持分離。未來的收藏、進度與作答紀錄應引用教材或題目 ID，不應直接嵌入教材本體。

## 教材產出與發布方向

```text
AI 產生候選教材
-> 儲存為未發布內容
-> 管理員在後台檢查與修改
-> 管理員發布
-> 前台顯示正式教材
```

AI 可協助產生單字、文章、文法與測驗題目，但不得未經人工審核直接發布。

## 教材內容資料模型方向

教材內文的共用欄位、Ruby 輸入／顯示策略、單字與文法的身分與收藏去重，以及 AI 產生內容時「不複製 ID、由 resolver 依自然鍵自動配對」的流程，統一定義於 `context/content-model.md`。重點原則：

- 每份含日文內文的教材都要能提供 Ruby、全日文純文字、每句繁中與整段繁中。
- 單字身分以辭書形自然鍵辨識；教材內文只保存出現位置與上下文，完整單字資料由單字表查得，收藏依身分去重（食べた／食べる 收藏後只會是同一筆食べる並顯示單字表完整資訊）。
- AI 產文章時輸出辭書形／讀音／詞性與文法 pattern，由 resolver 自動連到既有單字／文法或建立待審核草稿，不要求人工逐字配對。

## 技術策略

> 本檔是長期產品背景。**技術現況以 `docs/prd.md`、
> `docs/tasks/task-011-material-api-and-seed.md` 與程式碼為準**，本節只記錄一路走來的策略。

- 頁面與互動先以前端 TypeScript 假資料探索，隨切版驗證資料實際需要的欄位與關係。
- 教材頁穩定後才定稿資料模型與 API contract——單字、閱讀、對話三種教材已走完這一步，
  改由 MongoDB 儲存、經 Nuxt server routes 提供，程度篩選與分頁在伺服器端完成
  （Task 011）。教材內容的正本仍是 repo 裡的 TypeScript 資料檔，資料庫是可重跑 seed 重建的副本。
- 歌曲、文法、測驗尚未資料化，維持前述探索方式。
- `docs/schema.md` 僅是先前討論的資料庫草案，未隨 Task 011 的實作更新，不是現行規格。
- TTS 先驗證教材播放體驗，再設計批次產生與物件儲存流程。目前 `/api/tts` 只接受
  「教材類型＋教材 id＋單位 id」的內容座標，文字與 voice 由伺服器決定。

## Tech Stack

- Nuxt 4、Vue 3、TypeScript
- Tailwind CSS 4、FlyonUI
- Nuxt i18n
- Nuxt server routes
- MongoDB（既有，未來正式教材與使用者資料）
- Google Cloud Text-to-Speech（既有實驗）
- Zeabur（應用程式與 MongoDB 部署）
- Cloudflare R2（候選音檔儲存方案，尚未驗證）
- VOICEVOX（候選日文聲音方案，尚未驗證）

## UI / UX 方向

- 品牌色以紅、藍、白為主。
- 明亮、親切、清楚，但不幼兒化。
- 支援桌面與手機版。
- 教材需清楚標示類型及 JLPT 程度。
- 聲音、收藏、翻譯等學習操作應容易找到。
